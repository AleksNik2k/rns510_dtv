# RNS510 DTV

Данный проект представляет собой встроенное приложение для цифрового телевидения и радио, рассчитанное на головное устройство RNS 510. Код написан на C++ с использованием Qt 4, GStreamer и аппаратно-специфичных библиотек для DVB/TSI/обработки видео- и аудиопотоков.

Приложение работает как мультимедийный интерфейс для автомобильного приёмника: отображает список станций, выполняет поиск и выбор программ, показывает EPG, обрабатывает уведомления, управляет громкостью и взаимодействует с аппаратной платформой устройства.

---

## Что это за проект

Это не кроссплатформенное настольное приложение, а специализированный embedded-проект для автомобильной платформы. Основная логика находится в следующих компонентах:

- `main.cpp` — точка входа приложения и запуск основного GUI-сервиса;
- `play_ctrl.*` — главный контроллер UI и логики плеера;
- `dtv_core.*` — ядро DVB-логики: инициализация, сканирование, выбор станции, управление воспроизведением;
- `service_management.*` — работа со списком каналов, удалением, сортировкой и загрузкой данных;
- `src/QT/...` — виджеты интерфейса: панели, меню, окна информации, выбор канала, окно сканирования, индикаторы и др.;
- `src/libdtv/...` — библиотека низкоуровневой DVB-логики, таймингов, EPG, мультиплексов и служебных структур;
- `include/` — заголовки и основные API проекта;
- `lib/`, `moc/`, `qrc/` — сгенерированные/build-артефакты и ресурсы Qt.

---

## Основные возможности

Проект поддерживает следующие сценарии:

- просмотр цифрового ТВ и радио;
- автоматический и ручной поиск станций;
- загрузка и хранение списка станций;
- выбор канала по списку и переключение на следующую/предыдущую станцию;
- отображение информации о канале и программной сетке EPG;
- работа с аудиодорожками и выбором субтитров;
- регулировка громкости и состояние mute;
- окно системных сообщений и интерфейс статуса;
- поддержка записи потока;
- интеграция с MOST-подсистемой;
- аппаратная настройка качества отображения и масштабирования экрана;
- поддержка локализации через `tv_player_tr.ts`.

В коде есть явная привязка к железу и нестандартным системным файловым путям, например:

- `/media/localdata/DTV.ini`
- `/media/localdata/dvb_services.dat`
- `/dev/vt1622a`
- системная работа через QWS/Qt Embedded

Это важно: проект заточен под конкретную embedded-платформу и не является универсальным приложением для обычного Linux/desktop.

## Технологический стек

### Язык и GUI

- C++
- Qt 4 (QtGui, QtCore, QWS/embedded)
- Qt resource system (`Images.qrc`)
- QMainWindow-based UI

### Медиа и транспорт

- GStreamer 0.10
- GST plugins: `gstbase-0.10`, `gstapp-0.10`
- работа с MPEG-TS и демультиплексированием данных

### DVB / TSI / uCSI

Проект использует библиотеки и компоненты со следующими функциями:

- `libucsi` — разбор дескрипторов и таблиц PSI/SI;
- `tsi` — обработка транспортных потоков и тюнера;
- `dibcomcontrol` и `gpioctrl` — аппаратная поддержка и управление железом;
- `id3tag` — работа с метаданными MP3/медиафайлов;

### Сборка и генерация проекта

В каталоге `nbproject/` есть проект QMake, в том числе:

- `qt-Debug.pro`
- `qt-Debug.mk`
- `Makefile`

Судя по файлам, сборка ведётся под ARM-кросс-компилятор:

- `QMAKE_CXX = arm-linux-g++`
- `QMAKE_CC = arm-linux-gcc`
- `QT = core gui`
- `QMAKE_CXXFLAGS += -std=c++98`

Это означает, что проект изначально проектировался для кросс-компиляции под целевую плату, а не для обычной компиляции на x86 host.

## Сборка проекта

### Требования

Для сборки требуется целевая или кросс-среда с установленными компонентами:

- GCC/ARM cross-toolchain
- Qt 4 development package
- GStreamer 0.10 development package
- libxml2
- libucsi / libtsi
- `glib`, `gobject`, `gmodule`, `gthread`
- `libiconv`, `pthread`, `zlib`
- аппаратные библиотеки `dibcomcontrol`, `gpioctrl`

### Типичный процесс сборки

В проекте используется qmake-проект. Обычно сборка выглядит так:

```bash
cd /path/to/rns510_dtv
qmake nbproject/qt-Debug.pro
make -j$(nproc)
```

Если используется более стандартный проект NetBeans/Qt, возможно также применять `make` напрямую через корневой `Makefile` или проект в `nbproject`.

### Важная оговорка

Согласно файлам проекта, сборка настроена на ARM-среду и целевую платформу RNS 510. На обычной машине без правильного toolchain и библиотек проект, скорее всего, не соберётся "из коробки".

## Запуск

Приложение рассчитано на запуск на целевом устройстве, а не в обычной среде Linux desktop. В коде есть явная работа с embedded-окружением и framebuffer/Qt Server:

```cpp
QApplication app(argc, argv, QApplication::GuiServer);
QWSServer::setBackground(QBrush(QColor(0, 0, 0, 0)));
QWSServer::setCursorVisible(false);
```

Это подтверждает, что программа запускается как серверное GUI-приложение под embedded-средой.

На целевом устройстве бинарный файл обычно запускается напрямую, после чего приложение:

- поднимает основной цикл событий Qt;
- инициализирует `play_ctrl`;
- запускает `dtv`-ядро;
- отображает интерфейс и работает с телеприёмником.

## Основные классы и роль в архитектуре

### `play_ctrl`

Главный управляющий класс приложения. Здесь:

- создаётся и отображается главное окно;
- управляются таймеры, меню, список программ и переключение каналов;
- взаимодействует с `dtv` и с интерфейсом пользователя;
- обрабатывает события от пульта/канов/нетипичных сигналов;
- управляет сигналами MOST и системной информацией.

### `dtv`

Ядро DVB-процесса, которое отвечает за:

- инициализацию тюнера и драйверов;
- сканирование частот и поиск сетей;
- загрузку и обновление списка станций;
- выбор и воспроизведение активного канала;
- EPG и тайминг;
- запись потока и управление воспроизведением.

### `service_manager`

Отдельный слой управления перечнем услуг. Он отвечает за:

- загрузку списка DVB-станций;
- хранение, сортировку и удаление каналов;
- управление включением/выключением сервисов;
- перемещение/упорядочивание пользовательского списка.

## Описание runtime-подсистем

### Сканирование и работа со станциями

В коде присутствуют понятия:

- `DTV_Scan(...)`
- `DTV_Service_Select(...)`
- `DTV_Service_enable_disable(...)`
- `DTV_Index_To_Service(...)`

Это типичный набор функций app, где список каналов хранится в пользовательском файле и при старте заполняется в память.

### EPG

В проекте есть отдельные потоки EPG и временного обновления:

- `epg_thread`
- `epg_pf_thread`
- `time_update_thread`

Это подтверждает поддержку телепрограммы, актуальной информации и синхронизации времени через DVB.

### MOST

Код содержит интеграцию с MOST-подсистемой (`QMostInterface`, `QMostMediaPlayer`, `QMostTvList` и др.). Это указывает на поддержку автомобильной шины данных и обмен с другими устройствами головного модуля.
